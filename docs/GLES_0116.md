# iOS16 GLES installation pair 0116

This pair connects Sailfish's EAGL/Core Animation frontend and Mesa freedreno
(A618) to sweet's NativeAdreno ABI1. It is a compiled implementation, not a
verified hardware acceleration result. No runtime tests were run.

installing its library cannot enable the GLES frontend.

## What changed

- Mesa BO/import/submit/wait operations use NativeAdreno ABI1 and actual
  completion fences. Task-backed memory uses kernel physical cache maintenance.
- The EAGL frontend retains Sailfish's shader fixes. QuartzCore addresses were
  matched against the iPhone X 20H392 cache, with a runtime UUID check.
- `sweetgles=1` inserts the library only into backboardd; the matching kernel
  supplies dyld policy and task-backed IOSurface bitmap sharing.
- The recovered 0114 log showed successful GMU/SQE/CP startup but rejected
  provider publication at UCHE_CLIENT_PF (expected0x81, observed1). Patch0116
  uses the downstream A618 PERFSEL value1 with full8-bit readback validation.
- 120Hz presentation is requested. Actual frame rate remains unmeasured.

## Installation and rollback

Preparation uses a fresh read-only ADB-backed NBD snapshot and a local qcow2
filesystem overlay under `research/gles-install-0115/`. No previous Metal
installer cache is reused. The library's checksum, active root version and
cache UUID are checked before staging.

The staged delta preserves every changed block's original bytes and validates
all phone blocks before any write. The repository requires confirmation for
raw userdata writes. Recovery, bootloaders and partition layout are untouched.
The existing Metal bundle is retained.

For a normally mounted root, `tools/install-sweet-gles-root.py` supports inspect,
install and rollback. It keeps an installation record in
`/private/var/db/sweet-gles-install.json`. Boot without `sweetgles=1` to use the
previous graphics discovery mode. Exact block rollback is only suitable before
subsequent filesystem changes; its script refuses mismatched blocks.
